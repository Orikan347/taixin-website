# 全量 Blog 乾淨發布 Gate

狀態：`PENDING_USER_ACCEPTANCE`

## 目前事實（2026-07-13）

- GitHub 正式主線最新提交：`2033223 Improve blog SEO and GEO discovery`。
- 正式主線已有 36 篇 Vocus 同步文章與 SEO／GEO 基礎，但尚未有首頁作者介紹卡、文章可見署名與文末作者卡。
- 目前工作目錄相對正式主線為 `ahead 4 / behind 43`，混有課程與其他網站工作；不得直接從此工作目錄推送 `main`。
- 使用者驗收版本以 Vocus 公開清冊 36 篇與 94 張原圖為準；作者照片為官網既有 `img/portrait.jpg`，本機讀回 SHA-256 已一致。

## 正式發布前的硬 Gate

1. 使用者先在本機測試站確認文章列表、原圖、作者卡、文章署名、行動版與 CTA，並明確說「可以發布」。
2. 從最新 `origin/main` 建立乾淨工作目錄；不挾帶原工作目錄中的課程、後台、Worker、資料或其他未審核變更。
3. 唯讀取得 Vocus 公開作者清冊。若公開篇數與前次驗收不同，先列出差異；除非使用者在看見新篇數後明確授權「推上最新版」，否則停止發布並重新驗收。
4. 使用者明確授權最新版後，才在乾淨工作目錄執行完整同步，讓產生器重寫文章、原圖、RSS、sitemap、llms.txt 與作者可見性頁面。
5. 執行：

   - `python3 scripts/verify_vocus_catalog.py --site-root . --expected-public-count <本次公開 API 實際篇數>`
   - `python3 -m py_compile scripts/sync_vocus_catalog.py scripts/verify_vocus_catalog.py`
   - `git diff --check`
   - 桌機與 390px 手機的實際瀏覽器讀回。

6. 暫存前檢查 `git diff --name-only origin/main`。本輪只允許 Blog 產生物、Blog CSS、同步／驗證器、RSS／sitemap／robots／llms.txt 與本資料夾內的驗收紀錄；若出現其他網站功能或資料，停止並從暫存區移除。
7. 建立單一可回滾提交後，先在乾淨 worktree 執行 `scripts/verify_blog_release_scope.py`：它必須確認 worktree 無未提交檔、候選提交只含允許的 Blog 檔案，且所有 published-evidence audit 都是 `PASS`／`SYNC_ALLOWED_EVIDENCE_MATCHED`。若使用者明確只授權個人站發布，可加 `--allow-pending-vocus-canonical`，僅接受 `PERSONAL_SITE_DEPLOY_ALLOWED_PENDING_VOCUS_CANONICAL`；此例外不授權改 Vocus，也不代表跨站 canonical 已完成。
8. 只有上述 Gate 全部通過才推送。GitHub Pages 部署成功後，從公開網址讀回本次公開篇數、指定歷史文章原圖、作者卡、canonical／schema、robots、RSS 與 sitemap。

### 本機回放結果（2026-07-13）

- 去識別化 release-scope 測試：Blog-only 乾淨提交可通過；夾帶 `worker/` 檔或 evidence audit 非 PASS 時會被拒絕。
- 目前工作目錄刻意實跑結果：`FAIL`，原因是 worktree 不乾淨、與 `origin/main` 相比含有非 Blog 路徑，且既有 evidence audit 為 `BLOCK_SYNC_NO_OVERWRITE`。這是正確的防呆結果，不能在此工作目錄發布。

## 正式發布後仍待完成

- Search Console 與 Bing Webmaster Tools 需要網站擁有者登入既有帳號，提交 sitemap 並讀回處理／收錄狀態。
- 此動作只能證明搜尋引擎已接受或處理資料；不得承諾排名、流量或回答型 AI 必然引用。

## 回滾

如公開讀回失敗，只對該次 Blog 提交執行 `git revert <commit>` 後重新讀回；禁止 force push、刪除 Vocus 文章或覆寫其他人的提交。
