## 一、這次要解決的真正問題

目前頁面最大問題不是按鈕或文案單點，而是「對話沒有真正聽懂使用者」，所以會出現重複問句、沒有往下一步推進、報告不準、使用者不知道要回什麼。

新版不要把所有壓力交給 AI 自由回答，而是改成：

1. 用決策樹先收斂需求，讓每一步都有明確目的。
2. 重要判斷用選擇題，避免使用者不知道怎麼回答。
3. 自由輸入只放在需要「聽使用者原話」的位置。
4. AI 只負責把使用者資料整理成像真人的回覆，不負責亂猜價格、日期、名額或成效。
5. 最後一定能導向銷售天賦報告、課程內容、開課資訊、報名表單或 LINE 顧問。

## 五、A 樹：入口與基本資料

目的：先讓使用者知道這不是冰冷表單，是泰欣老師式引導。

> 銷售力不從心，因為從沒遇過李泰欣。
> 我會先了解你的背景，再幫你整理一份可以帶走的銷售天賦報告。

4. 西元出生年月日
5. 目前角色
6. 產業

## 六、B 樹：銷售天賦診斷

### B0 開始探索後的第一句

按下「開始探索」後，不能空白、不能直接質問。

固定格式：

> {姓名}，你好！我來分析一下你的報告，接下來會問你幾個問題。你不用想標準答案，照你平常銷售現場的反應選就好。

### B1 最想解決的問題，可複選

問題：

> 你現在最想解決的問題是什麼？可以複選。

選項與課程線索：

| 選項 | 線索 |
|---|---|
| 客戶不夠多 | 流量磁鐵 |
| 成交不了 | 成交地圖 |
| 看不懂客戶 | 直指人心 |
| 講不清楚價值 | 言之有物 |
| 很忙沒結果 | 極致效率 |
| 客戶追蹤很亂 | 極致效率 |
| 團隊無法複製 | 成交地圖 / 言之有物 / 極致效率 |
| 上台或表達有壓力 | 言之有物 |

### B2 最想達成的目標，可複選

問題：

> 如果接下來三個月只能先變好一件事，你最想看到哪幾個改變？

選項：

| 選項 | 線索 |
|---|---|
| 提升成交 | 成交地圖 |
| 建立信任 | 直指人心 |
| 增加名單 | 流量磁鐵 |
| 提高效率 | 極致效率 |
| 複製團隊 | 成交地圖 / 極致效率 |
| 提升表達 | 言之有物 |
| 看懂客戶 | 直指人心 |
| 找到自己的銷售優勢 | 銷售天賦報告 |

### B3 DISC 討厭情境第一題

問題：

> 在銷售裡，你最不喜歡哪一種狀況？

選項：

| 選項 | DISC 線索 |
|---|---|
| 拖很久不決定，會議也沒有結論 | D |
| 氣氛很冷，客戶不互動、不回應 | I |
| 一直被逼成交，關係變得很尷尬 | S |
| 資料不完整，規則不清楚，客戶一直改 | C |

### B4 DISC 討厭情境第二題

問題：

> 職場上你最受不了哪一種人？

選項：

| 選項 | DISC 線索 |
|---|---|
| 講很多但沒效率、沒結果 | D |
| 冷冰冰、不給回應、沒有熱情 | I |
| 太強勢、太逼人，讓人不舒服 | S |
| 不照流程、數字亂講、承諾沒根據 | C |

### B5 DISC 討厭情境第三題

問題：

> 客戶拒絕你的時候，你最自然的反應通常是哪一種？

選項：

| 選項 | DISC 線索 |
|---|---|
| 直接問原因，想趕快推進下一步 | D |
| 先把氣氛拉回來，讓對方願意繼續聊 | I |
| 先穩住關係，不想讓對方有壓力 | S |
| 補資料、補證據，把邏輯講清楚 | C |

### B6 真實情境自由輸入

問題：

> 最近一次客戶沒有往前走，他原話大概怎麼說？

用途：

1. 讓使用者真的講到話。
2. 用他的原話判斷異議類型。
3. 報告中的實戰建議要回到這一句，不可寫成通用模板。

### B7 報告產出前的過渡

文字：

> {姓名}，我有聽到你剛剛講「{使用者關鍵字}」。我把你的銷售天賦整理成表格，已經放在底下給你囉。
> 你看完覺得像你嗎？有準嗎？想繼續了解怎麼讓自己成長更快，直接回 yes。

### B8 銷售天賦報告內容

報告只放跟使用者有關的內容，不寫「我先不急著推薦課程」這種內部策略。

報告結構：

1. 姓名、DISC 主型、生涯運數
2. 你的銷售優點是：三點
3. 你的銷售天賦是：三點
4. 給你的實戰建議
5. Orikan 李泰欣送你一句話
6. 建議學習順序

### B9 銷售優點輸出規則

銷售優點來自 DISC，不要亂生。

| DISC | 使用者想聽的語氣 | 銷售優點方向 |
|---|---|---|
| D | 直接、結果、效率 | 抓重點、推進決策、把複雜事情變成行動 |
| I | 熱情、故事、感染力 | 拉近距離、帶動氣氛、讓產品變得有畫面 |
| S | 安心、關係、穩定 | 陪伴感、信任感、讓客戶願意慢慢說真話 |
| C | 邏輯、證據、結構 | 資料清楚、風險控制、讓客戶覺得可信 |

每份報告三點，白話寫，不照課程稿硬貼。

### B10 銷售天賦輸出規則

銷售天賦主要來自生涯運數主數；如果九宮連線有明顯優勢，可補一點整合優勢。總共三點。

規則：

1. 不要把 3、4、7 全部列出來造成資訊太多。
2. 只講主生涯運數的核心天賦。
3. 若有九宮連線，只補充為「整合優勢」。
4. 必須用白話，不照資料庫原稿貼上。

### B11 使用者覺得準

判斷詞：有、準、像、yes、對、很像、可以、繼續。

回覆：

> 太好了，有像就代表方向抓對了！我先把最適合你的三步學習順序打給你，讓你知道接下來怎麼學會更快。

下一步：C3 顯示三堂課文字版 + 課程路徑按鈕。

### B12 使用者覺得不準或看不懂

判斷詞：不準、不像、看不懂、不是、怪、錯。

不能重複同一句。必須先同理，再給選項。

回覆：

> 我懂，你不是要一份漂亮報告，你要的是看完真的覺得「這就是我」。那我幫你校正一下：是哪一段不像你？

選項：

| 選項 | 下一步 |
|---|---|
| 行為模式不像 | B3 重新計分，但保留原資料 |
| 銷售優點不像 | B6 補問真實情境 |
| 實戰建議不準 | F0 進異議/卡點樹 |
| 課程建議不適合 | C0 |

## 八、D 樹：課程內容問答

### D0 課程內容入口

### D1 流量磁鐵

使用者可問：學什麼、適合誰、能解決什麼、是不是錄播、價格。

標準利益點：

> 流量磁鐵主要是幫你處理「客戶從哪裡來」。不是叫你更努力亂發文，而是讓你知道怎麼把陌生人變成願意留下資料、願意被你追蹤的名單。

不能講太細的邊界：

> 細節工具和步驟會在課裡帶，你在頁面先看懂它能幫你解決什麼就好。

### D2 成交地圖

標準利益點：

> 成交地圖主要是幫你把成交流程變清楚。從第一次開口、提問、介紹產品、處理拒絕，到最後推進下一步，都不再只靠感覺。

可帶 MBAF / BAF，但不要公開細節：

> 課裡會教你怎麼把客戶在意的點，轉成聽得懂的價值和行動理由。

### D3 直指人心

標準利益點：

> 直指人心主要是幫你看懂人。不同客戶想聽的話不一樣，你會學會判斷對方的行為模式，知道該直接、該熱情、該安穩，還是該講邏輯。

### D4 言之有物

標準利益點：

> 言之有物主要是幫你把產品講得有力量。不是背話術，而是讓你的介紹有能量、有邏輯、有格局，客戶才會覺得這件事跟他有關。

### D5 極致效率

標準利益點：

> 極致效率主要是幫你處理業務最容易卡住的忙碌問題。你不是不努力，而是客戶資料、追蹤節奏和下一步沒有整理成系統，所以努力很容易散掉。

## 十、F 樹：異議處理

異議處理不能像機器人辯論，要用泰欣老師的方式：先接住，再釐清，再帶回價值。

### F0 異議偵測

| 使用者原話 | 異議類型 |
|---|---|
| 太貴、沒預算、價格高 | F1 太貴 |
| 我再想想、考慮一下 | F2 再想想 |
| 沒時間、太忙 | F3 沒時間 |
| 怕沒用、上過課沒效果 | F4 怕沒效果 |
| 要問主管、問老闆、問家人 | F5 要問決策者 |
| 我不確定適不適合 | F6 適合度 |
| 我看不懂、你講什麼 | B12 校正 |

### F1-F6 共用六步驟

1. 同理：先接住他的感受。
2. 釐清：你說的「貴 / 沒時間 / 怕沒效」，是指哪一部分？
3. 找依據：你會這樣想，是因為以前遇過什麼狀況？
4. MBAF / BAF 回應：用利益、優勢、特色、行動理由回應。
5. 確認：這樣有回答到你的擔心嗎？
6. 下一步：回到課程、報名、LINE 或顧問協助。

### F1 太貴

D 型：

> 我懂，你在意的是投資回收，不是單純價格。那我直接幫你看：你現在最需要先補的是名單、成交、信任、表達，還是效率？先補對，這筆錢才會變成工具，不是壓力。

I 型：

> 我懂，聽到價格會先停一下很正常。但重點不是花錢上課，而是你學完後能不能把客戶聊得更有感、把價值講得更動人。你先跟我說，你最想讓哪一段銷售變得更有把握？

S 型：

> 我懂，你不是不想學，是不想花了錢又沒有安全感。那我們先不用急著決定，我先幫你看哪一堂最符合你現在的狀況，讓你有把握再往下一步走。

C 型：

> 我懂，你需要看清楚這筆投入對應到什麼能力。那我會先把課程分成名單、成交、信任、表達、效率五種能力，再對照你目前最缺哪一塊。

### F2 再想想

回覆方向：

> 可以，我不會硬推你。但我想幫你把「想想」拆清楚：你是在想價格、時間、適合度，還是怕學了用不上？

下一步選項：價格 / 時間 / 適合度 / 怕沒效果。

### F3 沒時間

回覆方向：

> 我懂，很多業務不是不想學，是已經忙到沒有空整理自己。可是越忙越需要系統，不然每天都在救火。你目前比較卡在客戶追蹤、行程安排，還是成交下一步沒有整理？

優先導向：極致效率。

### F4 怕沒效果

回覆方向：

> 我懂，你不是排斥學習，你是在保護自己不要再浪費時間。那我們先不講保證，我先看你以前學了沒用，是因為不適合產業、沒有練習場景，還是回去不知道怎麼用？

### F5 要問決策者

回覆方向：

> 可以，這很正常。你不是一個人決定，就要把決策者在意的東西講清楚。通常主管會看三件事：要解決什麼問題、學完怎麼落地、花這筆錢換到什麼能力。

下一步：提供給主管看的課程利益摘要。

### F6 不確定適不適合

回覆方向：

> 我懂，你不是不想學，是怕選錯。那我先用三個問題幫你判斷：你現在最想改善的是名單、成交、信任、表達，還是效率？

下一步：C0。

## 十一、DISC 語氣規則

同一句內容，要依 DISC 改說法。

| DISC | 回覆原則 | 避免 |
|---|---|---|
| D | 短、準、結果導向，直接給結論 | 太多情緒鋪陳 |
| I | 熱情、有畫面、有鼓勵，像真人聊天 | 冷冰冰、太表格化 |
| S | 溫暖、安心、不逼迫，讓他覺得被理解 | 太強勢、太快成交 |
| C | 條理、依據、步驟、風險說清楚 | 空泛熱情、沒有邏輯 |

泰欣老師預設語氣：I 型影響型，熱情、有力量、像真人，不講 AI 味重的詞。

禁用語感：

1. 「你先跟我說清楚一點」
2. 「我目前不直接猜」
3. 「不急著推薦課程」
4. 「節奏很卡」
5. 「你想把哪一句話講得更有力量」

## 十八、三輪批判與改進

這一區用來反推目前決策樹還沒有想夠深的地方。目標不是讓流程更複雜，而是讓它上線後更像真人、更穩、更會成交。

### 第一輪批判：使用者體驗會不會卡住

#### 問題 1：三個問題不一定每次都夠

現在規劃是先問三個問題，再整理說明。這是對的，因為使用者不喜歡一直被問。但風險是：有些人回答太短、太含糊，三題後系統其實還不夠判斷。

改進：

1. 設計 `confidence_score`。
2. 三題後如果資料夠，就進整理說明。
3. 三題後如果資料不夠，不要硬出報告，只補一題最關鍵的問題。
4. 補問不得超過兩次，避免變成問卷。

例：

> 我已經抓到你的方向了，但還差一個關鍵：你現在最常卡住的是客戶不相信、價格談不下來，還是後續追蹤斷掉？

#### 問題 2：選項不能太像內部分類

如果按鈕寫「價格異議」「需求感不足」「價值感不足」，使用者會覺得像系統，不像聊天。

改進：

按鈕要用客戶聽得懂的話。

| 內部分類 | 前台按鈕 |
|---|---|
| 價格異議 | 客戶覺得太貴 |
| 需求感不足 | 客戶覺得現在不需要 |
| 價值感不足 | 客戶不確定有沒有效 |
| 決策者異議 | 客戶說要問別人 |
| 時間異議 | 客戶說最近沒空 |

#### 問題 3：「以上的說明都清楚嗎？」要固定，但不能讓前面每段都一樣

泰欣老師指定每段說明後要收尾：

> 以上的說明都清楚嗎？

這句可以固定，但前面的說明不能模板化。否則使用者會覺得每輪都一樣。

改進：

每個說明節點要包含三個元素：

1. 先引用使用者剛剛說的原話。
2. 再給一段泰欣式判斷。
3. 最後才接「以上的說明都清楚嗎？」

例：

> amy，我有聽到你剛剛講「客戶都說再想想」。這句話通常不是客戶完全沒興趣，而是他心裡還有一個點沒有被你問出來。你現在要補的不是更用力介紹產品，而是先把他猶豫的原因拆出來。
>
> 以上的說明都清楚嗎？

#### 問題 4：每次說明後不能只給一個按鈕

泰欣老師已確認：每次說明後要有四顆按鈕。

固定結構：

1. 延伸問題一
2. 延伸問題二
3. 延伸問題三
4. 我都清楚了

規則：

1. 前三顆按鈕是客戶可能想追問的下一個問題。
2. 第四顆永遠是「我都清楚了」。
3. 點「我都清楚了」才進入銷售天賦報告、課程推薦或 CTA。
4. 前三顆按鈕必須根據上一輪回答生成，不可固定。
5. 前台按鈕只能用客戶看得懂的話，不可出現內部分類、DISC 代號、節點代號、異議分類或系統語。

例：

> 以上的說明都清楚嗎？

按鈕：

1. 客戶覺得太貴
2. 客戶說再想想
3. 客戶想問別人
4. 我都清楚了

#### 問題 5：要允許使用者跳過診斷

有些人不是來測銷售天賦，他只是想看課程時間或價格。若逼他填完整診斷，會流失。

改進：

入口要保留低摩擦分流：

1. 找出銷售天賦
2. 了解哪堂課適合我
3. 直接看課程內容
4. 直接看開課時間與金額
5. 直接問 LINE 顧問

### 第二輪批判：銷售轉換會不會太硬或太鬆

#### 問題 1：不能太早推課

使用者還沒認同診斷前，直接推薦課會像廣告。

改進：

推薦課程前要先拿到一個小認同：

1. 先整理他的現況。
2. 問「以上的說明都清楚嗎？」
3. 使用者點「我都清楚了」。
4. 才進報告或課程推薦。

#### 問題 2：「我都清楚了」不是結束，而是進下一層

「我都清楚了」要依目前場景執行不同動作：

| 目前場景 | 點「我都清楚了」後 |
|---|---|
| 銷售天賦診斷 | 產出銷售天賦報告 |
| 課程適配 | 顯示建議學習順序 |
| 課程內容 | 顯示適合誰、下一步 CTA |
| 價格說明 | 顯示報名表單 / LINE 顧問 |
| 異議處理 | 回到課程推薦或顧問諮詢 |

#### 問題 3：價格異議要再拆細

客戶說貴，不一定是真的沒錢。

價格樹要拆成：

1. 覺得現在不需要。
2. 覺得效果不確定。
3. 想跟別人比較。
4. 真的預算不足。
5. 需要問主管 / 家人。
6. 想知道有沒有優惠或分期。

每一類下一句不同。

例：客戶點「客戶覺得太貴」後，下一句：

> 我懂，客戶卡在價格，很多時候不是單純嫌貴，而是他還沒看見「為什麼這筆錢跟他有關」。我先幫你拆一下：你的客戶說貴的時候，通常比較像哪一種？
>
> 以上的說明都清楚嗎？

按鈕：

1. 覺得現在不需要
2. 不確定有沒有效
3. 想跟別人比較
4. 我都清楚了

#### 問題 4：要有「現在不適合買」的分支

如果所有路徑都推報名，會失去信任。有些人可能只是來看內容、預算不夠、時間不對。

改進：

增加低壓 CTA：

1. 先下載銷售天賦報告。
2. 先加 LINE 問顧問。
3. 先看課程介紹。
4. 等下一期通知。

這樣不會把還沒準備好的人逼走，也能留下 Lead。

#### 問題 5：課程推薦不能只推一堂，要給「路徑」

使用者想知道不是只有「買哪堂」，而是「我應該怎麼變強」。

改進：

每次推薦至少給：

1. 第一堂：現在最需要補的能力。
2. 第二堂：補完第一能力後的下一個槓桿。
3. 第三堂：讓能力放大或複製。

例：

> 建議學習順序：
> 1. 《直指人心》：先看懂客戶心裡真正卡什麼。
> 2. 《成交地圖》：把客戶猶豫接成下一步。
> 3. 《言之有物》：把價值講得更有畫面、更有感。

### 第三輪批判：系統能不能穩定實作

#### 問題 1：不能只寫文案，要寫成狀態機

如果只靠文案判斷，前端會再次出現重複同一句。

改進：

每個節點都要有：

| 欄位 | 用途 |
|---|---|
| `node_id` | 節點唯一 ID |
| `stage` | profile / diagnosis / explanation / report / course / objection / cta |
| `input_type` | choice / multi_choice / text / action |
| `required_context` | 需要哪些資料才能進入 |
| `explanation_template` | 說明文字 |
| `followup_buttons` | 前三顆客戶看得懂的延伸問題 |
| `clear_button_action` | 「我都清楚了」後要去哪 |
| `fallback_node` | 判斷失敗時去哪 |
| `max_repeat` | 同節點最多出現幾次 |

#### 問題 2：要有重複防呆

目前最嚴重的問題是同一句一直重複。這不是文案問題，是狀態沒有前進。

改進：

1. 同一個 `node_id` 不可連續輸出超過一次。
2. 同一個說明模板不可在同一 session 出現兩次。
3. 如果連續兩次無法判斷，就進 H 樹回收，不再問同一句。
4. 使用者點按鈕後，必須立即改變 `conversation_stage`。

#### 問題 3：AI 不能直接決定價格、名額與保證

Gemini 或 OpenAI 可以用來潤飾語氣，但不能負責事實。

改進：

1. 課程日期、價格、名額、付款方式只讀 `course_offerings`。
2. AI 回答課程問題時只能引用白名單內容。
3. 沒有資料的欄位，轉 LINE 顧問，不自行補。
4. 成效數字、案例、退費保證未確認不得出現在公開頁。

#### 問題 4：要設計人工接手

有些問題 AI 不該硬答，例如付款、名額、企業包班、特殊產業、退款政策。

改進：

增加 `handoff_required` 條件：

1. 問名額。
2. 問付款方式。
3. 問優惠或分期。
4. 問企業包班。
5. 問退費保證。
6. 問私人個案太複雜。
7. 使用者連續兩次表示看不懂或不滿意。

接手文案：

> 這個我不想亂回答你，因為牽涉到最新名額或付款細節。我幫你把剛剛的資料整理好，直接給 LINE 顧問接續，這樣你不用重講一次。

#### 問題 5：後台不只存名單，也要存「路徑」

如果只存姓名、Email，成交聯盟未來拿不到有價值的資料。

改進：

Lead Hub 要存：

1. 使用者走過哪些節點。
2. 哪些按鈕被點。
3. 哪一句自由輸入觸發哪個判斷。
4. DISC 分數與信心分數。
5. 推薦課程原因。
6. 使用者是否點「我都清楚了」。
7. 使用者是否下載或分享報告。
8. 是否轉 LINE 或報名表單。

這樣未來成交聯盟可以知道：這個人不是只有「填表」，而是卡在價格、信任、效率，還是成交流程。

#### 問題 6：要有樹狀圖版本控管

上線後一定會改問題、改按鈕、改課程說法。如果沒有版本控管，舊 Lead 會對不上當時規則。

改進：

1. `decision_tree_version` 寫入每筆 Lead。
2. 每次改樹都新增版本號。
3. 報告也保存當時版本。
4. 後台可看哪個版本轉換率較高。

## 十九、DISC 行為模式判斷樹

這個網站可以在幾個問答裡做出 DISC 初判，但要定義清楚：這是銷售情境下的行為模式判斷，不是醫療診斷，也不是完整心理測驗。

### 判斷原則

1. 不直接問「你是 D/I/S/C 哪一型」。
2. 用他討厭什麼、遇到客戶怎麼反應、職場最受不了什麼來推估。
3. 每題四個選項，各自對應 D/I/S/C。
4. 三題後可得到初步主型；若分數接近，回覆採混合型。
5. 前台可以說「你比較像結果導向 / 感染帶動 / 穩定關係 / 邏輯分析」，不要直接把 DISC 當成唯一標籤。

### DISC 初判題一：銷售中最討厭的事

問題：

> 在銷售裡，你最不喜歡哪一種狀況？

| 前台選項 | 後台線索 | 代表意義 |
|---|---|---|
| 拖很久不決定，講半天沒有結果 | D | 討厭沒效率、沒結論 |
| 氣氛很冷，客戶不互動、不回應 | I | 在意互動、情緒、連結 |
| 一直被逼成交，關係變得很尷尬 | S | 在意關係、安全感、舒服 |
| 資料不完整，規則不清楚，客戶一直改 | C | 在意邏輯、證據、規則 |

### DISC 初判題二：職場最受不了的人

問題：

> 職場上你最受不了哪一種人？

| 前台選項 | 後台線索 | 代表意義 |
|---|---|---|
| 講很多但沒效率，事情沒有往前走 | D | 追求速度與成果 |
| 冷冰冰、不給回應，讓現場很無聊 | I | 需要熱度、回應和氣氛 |
| 太強勢、太逼人，讓人壓力很大 | S | 重視和諧與信任 |
| 不照流程、數字亂講，承諾沒根據 | C | 重視準確與可驗證 |

### DISC 初判題三：客戶拒絕時的自然反應

問題：

> 客戶拒絕你的時候，你第一個反應通常是哪一種？

| 前台選項 | 後台線索 | 代表意義 |
|---|---|---|
| 直接問原因，想趕快推進下一步 | D | 直接處理問題 |
| 先把氣氛拉回來，讓對方願意聊 | I | 先恢復互動感 |
| 先穩住關係，不想讓對方有壓力 | S | 先保護關係 |
| 補資料、補證據，把邏輯講清楚 | C | 先補足理由 |

### DISC 初判題四：客戶說「我再想想」時的直覺

問題：

> 當客戶說「我再想想」，你心裡最常出現哪一個想法？

| 前台選項 | 後台線索 | 代表意義 |
|---|---|---|
| 他到底卡在哪裡，我想直接問清楚 | D | 想快速拆問題 |
| 氣氛是不是不夠好，我想再拉近一點 | I | 想補情緒和關係 |
| 我是不是給他太大壓力，我想慢慢來 | S | 想降低壓力 |
| 我是不是證據不夠，我想再補資料 | C | 想補邏輯和依據 |

### DISC 分數規則

| 狀況 | 判斷 |
|---|---|
| 某型 3 分以上 | 主型明確 |
| 最高分 2 分，第二高 2 分 | 混合型 |
| 四型分散 | 需要補問一題 |
| 使用者自由輸入與選項衝突 | 用自由輸入調整信心分數，不直接推翻 |

### DISC 回話方法

同一個意思，四型要用不同說法。

#### D 型：結果導向

他想聽：

1. 結論是什麼。
2. 下一步做什麼。
3. 怎麼更快有效。

回覆方式：

> 我直接講重點：你不是不會賣，而是現在成交流程還不夠快、不夠清楚。你要先補的是把客戶卡點問出來，再推進下一步。

適合按鈕：

1. 客戶到底卡在哪
2. 下一步怎麼推進
3. 怎麼更快成交
4. 我都清楚了

#### I 型：影響帶動

他想聽：

1. 他有感染力。
2. 怎麼讓客戶有感覺。
3. 怎麼把話講得更有畫面。

回覆方式：

> 我聽得出來，你其實很適合用故事和溫度打動客戶。你現在要補的不是更用力介紹，而是讓客戶一聽就覺得「這跟我有關」。

適合按鈕：

1. 怎麼講得更有感
2. 怎麼讓客戶有畫面
3. 怎麼讓氣氛更好
4. 我都清楚了

#### S 型：穩定關係

他想聽：

1. 不用急著逼客戶。
2. 關係和信任是優勢。
3. 可以一步一步讓客戶安心。

回覆方式：

> 我懂，你不是不想成交，你是不想讓客戶覺得被逼。這其實是你的優勢，因為你適合用穩定和信任讓客戶慢慢說真話。

適合按鈕：

1. 怎麼讓客戶更安心
2. 怎麼不逼也能成交
3. 怎麼建立信任
4. 我都清楚了

#### C 型：邏輯分析

他想聽：

1. 判斷依據是什麼。
2. 步驟怎麼走。
3. 風險怎麼降低。

回覆方式：

> 我先把邏輯講清楚：你現在不是缺熱情，而是需要一套更完整的判斷順序。先確認客戶問題，再確認決策條件，最後才介紹方案。

適合按鈕：

1. 判斷依據是什麼
2. 步驟怎麼走
3. 怎麼降低風險
4. 我都清楚了

### DISC 與銷售天賦報告的關係

報告裡可以寫：

> 你目前比較像「結果導向型」，所以你的銷售優點是抓重點、推進快、願意處理問題。

不要寫：

> 你是 D 型，所以你一定怎樣。

前台要保留溫度，避免把人貼標籤。

## 二十、前台文案核對規則

這個網站是給潛在學員看的，不是給內部人員看的，所以前台所有文字都要過核對。

### 前台禁止出現

1. `node_id`
2. `stage`
3. `confidence_score`
4. `handoff_required`
5. `decision_tree_version`
6. 價格異議
7. 價值感不足
8. 需求感不足
9. 內部分類
10. 演算法判斷
11. 我目前不直接猜
12. 不急著推薦課程
13. 你先跟我說清楚一點

### 前台要改成這樣說

| 內部用語 | 前台用語 |
|---|---|
| 價格異議 | 客戶覺得太貴 |
| 價值感不足 | 客戶不確定有沒有效 |
| 需求感不足 | 客戶覺得現在不需要 |
| 決策者異議 | 客戶說要問別人 |
| confidence_score 不足 | 我還差一個關鍵就能判斷更準 |
| handoff_required | 這個細節我幫你交給顧問確認 |
| lead | 你的資料 / 你的報告 |
| CTA | 下一步 |

### 每段說明固定格式

1. 引用使用者原話。
2. 用泰欣老師語氣整理判斷。
3. 接「以上的說明都清楚嗎？」
4. 顯示四顆按鈕：三個延伸問題 + 我都清楚了。

範例：

> amy，我有聽到你剛剛講「客戶覺得太貴」。這通常不是單純價格問題，而是客戶還沒有看見這筆錢跟他的結果有什麼關係。你下一步要補的，是先問出他在意的是預算、效果，還是跟別人比較。
>
> 以上的說明都清楚嗎？

按鈕：

1. 客戶覺得現在不需要
2. 客戶不確定有沒有效
3. 客戶想跟別人比較
4. 我都清楚了

### 文案核對方法

正式實作前，必須掃描前台可見文案：

1. 不得出現內部欄位名。
2. 不得出現開發者語氣。
3. 不得出現未確認日期、名額、保證和成效數字。
4. 每一段說明後都要有四顆按鈕。
5. 每一顆按鈕都要像客戶會講的話。
6. DISC 結果只說「比較像」，不做絕對貼標籤。

## 二十一、批判後的新版核心規則

### 規則 1：三題後才整理，但可依信心補問一題

預設問三題；若信心不足，最多補問兩題。

### 規則 2：每次整理說明後，固定四顆按鈕

格式：

1. 延伸問題一
2. 延伸問題二
3. 延伸問題三
4. 我都清楚了

### 規則 3：「我都清楚了」是轉換門

點下後才進：

1. 銷售天賦報告
2. 建議學習順序
3. 課程資訊
4. 報名 / LINE CTA

### 規則 4：所有按鈕用客戶語言，不用內部分類

不要寫「價格異議」，要寫「客戶覺得太貴」。

不要寫「價值感不足」，要寫「客戶不確定有沒有效」。

不要寫「下一個問題 A」，要直接寫客戶會想追問的那句話。

### 規則 5：自由輸入只用來抓原話，不讓使用者自己想流程

每輪都要給按鈕，使用者可以打字，但不用靠打字才能前進。

### 規則 6：AI 負責口吻，不負責事實

AI 可以整理「像泰欣老師的說明」，但價格、日期、名額、保證和案例都必須從資料表或顧問確認。

### 規則 7：重複同一句是系統錯誤，要有防呆

同一節點不可連續輸出兩次。連續判斷失敗，立刻進回收節點。

### 規則 8：Lead Hub 要存完整路徑，不只存名單

未來成交聯盟要能看出這個 Lead 的問題、意圖、卡點、推薦原因和 CTA 行為。

### 規則 9：DISC 是後台判斷，前台用白話呈現

後台可以存 D/I/S/C 分數；前台要說「比較像結果導向、感染帶動、穩定關係、邏輯分析」，避免讓使用者覺得被貼標籤。

## 二十七、2026-07-11 課程介紹決策樹定稿

這一版的原則是：先讓學生用五個利益點快速選方向；學生點進某一堂課後，才說那堂課的內容並繼續提問。第一層不能一次丟出五堂課的教材架構。

```text
三題探索完成
└─ 了解課程介紹
   └─ 五堂課利益點總覽
      ├─ 流量磁鐵
      ├─ 成交地圖
      ├─ 直指人心
      ├─ 極致效率
      └─ 言之有物
         └─ 點其中一堂
            └─ 該堂課的三個深入問題
               └─ 每答一題，移除已答問題，保留未答問題與收尾選項
```

### D0 五堂課利益點總覽

老師第一句：

> 好，我先用最簡單的方式，讓你看懂五堂課各自能幫你什麼。你看到有興趣的，就直接點進去，我再繼續跟你說。

學生看到的五堂課：

| 課程 | 第一層利益點 |
|---|---|
| 流量磁鐵 | 先把名單來源建立起來，不再只靠介紹或運氣等客戶。 |
| 成交地圖 | 把從第一印象到成交的每一步整理清楚，知道下一句怎麼接。 |
| 直指人心 | 看懂不同客戶在意什麼，知道怎麼說他才聽得進去。 |
| 極致效率 | 把客戶資料、時間和追蹤整理好，解決每天很忙卻沒有結果。 |
| 言之有物 | 把產品價值說得清楚、有感，也能用來帶人和影響團隊。 |

收束句：

> 你想先了解哪一堂？直接點課程名稱就好。

這一層只有五個課程選項，不出現 MBAF、DISC、YPD、天地人網等細節。

### D1 流量磁鐵

開場：

> 流量磁鐵先幫你處理「客戶從哪裡來」。它不是叫你一直發內容，而是把線上、線下、社群、個人品牌、實體場景和人脈整理成可以執行的開發方向。

| 學生問題 | 回答重點 |
|---|---|
| 天地人網怎麼找名單？ | 線上、線下、社群、個人品牌、實體場景和人脈一起看，找到適合自己產業的開發方式。 |
| 名單找到後怎麼管理？ | 用存、記、分、細留下資料、記錄互動、分辨狀態和安排下一步。 |
| 沒有名單的人適合嗎？ | 先處理不知道去哪裡找客戶，再把找到的人留下來和分清楚。 |

### D2 成交地圖

開場：

> 成交地圖先幫你處理「客戶來了怎麼成交」。它把第一印象、核心問題、產品介紹和成交收尾排成一條路，讓你不必每次都靠臨場猜下一句。

| 學生問題 | 回答重點 |
|---|---|
| 怎麼問出客戶真正的需求？ | 用五大核心問題問背景、困擾、影響、期待和下一步。 |
| MBAF 怎麼介紹產品價值？ | 先講客戶得到的利益，再說優勢，最後才補產品特性。 |
| 客戶拒絕時要怎麼處理？ | 先理解，再問清楚疑慮來源，用 MBAF 重新論證價值，確認問題有沒有解決，再帶回方案。 |

### D3 直指人心

開場：

> 直指人心先幫你處理「怎麼看懂客戶」。你會從互動中的行為線索判斷對方在意什麼，再調整說法，不再每個人都用同一套。

| 學生問題 | 回答重點 |
|---|---|
| 怎麼從互動看出客戶類型？ | 觀察外貌舉止、聲音語調、回答速度和在意的問題，再回到 DISC 四型判斷。 |
| D、I、S、C 要怎麼說？ | D 重結果效率、I 重感覺互動、S 重安全穩定、C 重資料邏輯。 |
| 怎麼讓客戶更快建立信任？ | 先讓對方感覺被聽懂，再用適合他的方式提問、說明和追蹤。 |

### D4 極致效率

開場：

> 極致效率先幫你處理「很忙但沒結果」。它把客戶資料、時間安排、追蹤和下一步整理好，讓你的時間回到真正重要的客戶身上。

| 學生問題 | 回答重點 |
|---|---|
| 怎麼處理業務員每天很忙？ | 把重複找資料、回想對話和安排時間的工作整理起來，把時間留給客戶互動和成交。 |
| 客戶資料怎麼整理才不會漏？ | 用存、記、分、細保存資料、互動內容、客戶狀態和下一步。 |
| 時間碼和行事曆怎麼配合？ | 替不同工作留下固定時間，並把客戶下一步直接放進行事曆。 |

### D5 言之有物

開場：

> 言之有物先幫你處理「怎麼把價值說清楚」。它不是只教你講得漂亮，而是讓你的話有能量、有邏輯、有格局，客戶和團隊都聽得懂。

| 學生問題 | 回答重點 |
|---|---|
| 能量、邏輯、格局是什麼？ | 能量讓人願意聽，邏輯讓人聽得懂，格局讓人看見未來和關係。 |
| 面對不同對象要怎麼說？ | 向上讓決策者看見方向和價值，平級讓人願意合作，向下讓團隊知道怎麼執行。 |
| 30 秒電梯簡報和 YPD 能幫什麼？ | 前者幫你短時間講清楚，後者把不敢說、說不清楚的地方拆開練習。 |

### D6 每堂課的共同收尾

每一個深入問題回答完都接：

> 你還想繼續了解哪一段？
>
> 以上的說明都清楚嗎？

按鈕規則：

1. 還沒回答的課程問題優先留下。
2. 已回答的問題不能再出現。
3. 問完三題後，提供「看另一堂課」「回到五堂課介紹」「找出我的銷售天賦」「我都清楚了」。
4. 不同按鈕不可對應同一段回答。
